# eFootball Bot — Полное описание проекта

## Что это

Telegram-бот для управления лигами eFootball 2026. Позволяет игрокам регистрироваться, вступать в лиги, отчитываться о результатах матчей, оспаривать итоги и смотреть турнирные таблицы. Администраторы управляют лигами, одобряют заявки, проводят жеребьёвку и разрешают споры.

## Архитектура

Проект построен по **чистой архитектуре**:

```
Telegram API
     │
     ▼
┌─────────────────────┐
│   bot/handlers      │  ← UI-слой: приём сообщений, клавиатуры, стейт-машина
└────────┬────────────┘
         │
         ▼
┌─────────────────────┐
│      service        │  ← Бизнес-логика: матчи, расписание, ELO
└────────┬────────────┘
         │
         ▼
┌─────────────────────┐
│    repository       │  ← Слой данных: SQL-запросы к PostgreSQL
└────────┬────────────┘
         │
         ▼
┌─────────────────────┐
│    PostgreSQL 16    │
└─────────────────────┘
```

### Паттерны

- **Worker Pool** — 50 горутин параллельно обрабатывают Telegram-апдейты (буфер 200)
- **State Machine** — `sync.Map` хранит состояние ввода пользователя (регистрация, ввод результата)
- **Admin Cache** — кэш прав администратора с TTL 5 мин в `sync.Map`
- **Graceful Shutdown** — обработка `SIGTERM`/`Interrupt` с завершением горутин

## База данных

### Таблицы

| Таблица | Назначение |
|---------|-----------|
| `users` | Реестр игроков: telegram_id, рейтинг, ранг, team_power, язык |
| `seasons` | Турнирные сезоны со статусом (pending / active / finished) |
| `leagues` | Отдельные лиги внутри сезона: уровень, тип раундов, максимум игроков |
| `league_members` | Many-to-many: участник ↔ лига, очки, победы/ничьи/поражения, голы |
| `matches` | Матчи: двойное хранение голов (claimed vs final), статус, счётчик споров |
| `disputes` | Архив оспоренных матчей с решением администратора |
| `admins` | Роли (admin / super_admin) |

### Миграции (Goose)

13 последовательных SQL-миграций, применяются автоматически при запуске:

```
001 → users
002 → seasons
003 → leagues
004 → league_members (со статистикой)
005 → matches (claimed + final scores)
006 → disputes
007 → admins
008 → роли admin, статус archived у лиг
009 → индексы для производительности
010 → rating + team_power у пользователей
011 → rank
012 → language
013 → default language = 'uz'
```

## Логика матчей

### Жизненный цикл результата

```
[scheduled]
     │
     │ HomePlayer: /result matchID 3:1
     ▼
[pending_confirm]  ──── Уведомление away-игрока ────►  ✅ Розиман / ❌ Розимасман
     │                                                        │         │
     │ Confirm                                                │         │ Dispute
     ▼                                                        │         ▼
[confirmed]  ◄──────────────────────────────────────────────┘    [disputed] → home re-enters
     │                                                                         ↑___3+ → admin
     ▼
  • Применяются stats (очки/голы/победы) к league_members
  • Пересчёт позиций в таблице
  • Пересчёт ELO обоих игроков
  • Уведомление в группу (если GROUP_CHAT_ID задан)
```

### ELO-расчёт

```
Expected = 1 / (1 + 10^((opponent_rating - your_rating) / 400))
K = 32
Result = 1.0 (win) | 0.5 (draw) | 0.0 (loss)

TeamPowerBonus = (awayTP - homeTP) / 500 * 5   (cap ±10)
NewRating = OldRating + K * (Result - Expected) ± TeamPowerBonus
MinRating = 100
```

### Ранги (по перцентилю среди всех игроков)

| Ранг | Порог |
|------|-------|
| 👑 Легенда | Топ 1% |
| 🥇 Мастер | Топ 5% |
| 🥈 Эксперт | Топ 15% |
| 🏅 Ветеран | Топ 30% |
| ⚡ Про | Топ 50% |
| 🔥 Любитель | Топ 70% |
| 💫 Новичок+ | Топ 85% |
| 🥉 Новичок | Остальные |

## Алгоритм жеребьёвки

Реализована **круговая система** (`schedule.go`):

- Первый игрок фиксирован, остальные ротируются по кругу
- Нечётное количество → один получает "bye" (skip), пропускается
- **Одиночный круг**: n−1 туров, n/2 матчей в туре
- **Двойной круг**: повтор с инверсией хозяин/гость (туры n ... 2n−2)

## Команды бота

### Игровые команды

| Команда | Действие |
|---------|---------|
| `/start` | Регистрация: язык → имя → team power |
| `/join ИмяЛиги` | Подать заявку в лигу |
| `/result ID 3:1` | Хозяин заявляет счёт матча |
| Кнопка ✅ | Гость подтверждает результат |
| Кнопка ❌ | Гость оспаривает результат |

### Команды администратора

| Команда | Требования | Действие |
|---------|-----------|---------|
| `/admin add telegramID [super]` | super_admin | Добавить администратора |
| `/admin remove telegramID` | super_admin | Удалить администратора |
| `/admin resolve matchID 3:1` | admin+ | Вручную разрешить спор |
| Кнопка «Управление лигами» | super_admin | CRUD лиг из меню |
| Жеребьёвка (из меню) | super_admin | Сгенерировать расписание |
| Одобрить заявку | super_admin | Принять/отклонить участника |

### Inline callbacks (кнопки)

```
confirm_ID       — подтвердить результат
dispute_ID       — оспорить результат
table_ID         — турнирная таблица лиги
schedule_ID      — расписание матчей пользователя
lang_uz/ru/tg    — выбор языка
change_lang      — смена языка
edit_name        — редактировать имя
edit_team_power  — изменить team power
admin_manage_leagues — панель управления лигами
league_archive_ID    — архивировать лигу
league_delete_ID     — удалить лигу
view_mems_ID         — просмотр участников
kick_leagueID_userID — исключить участника
```

## Многоязычность

Поддерживается 3 языка: **Uzbek (uz)**, **Русский (ru)**, **Тоҷикӣ (tg)**.

Реализация через простую map в `i18n/i18n.go`:

```go
func T(lang, key string) string { ... }
```

Язык выбирается при регистрации и сохраняется в `users.language`. Uzbek — язык по умолчанию (fallback).

## Инициализация при запуске (main.go)

1. Загрузка конфигурации из `.env`
2. Применение Goose-миграций (авто-создание/обновление схемы)
3. Инициализация `pgxpool` (20 max connections, 5 min idle, 30s timeout)
4. Создание репозиториев → сервисов → хендлеров
5. Запуск 50-воркерного пула (очередь задач буфер 200)
6. Подключение к Telegram (polling, timeout 60s)
7. Обработка SIGTERM/Interrupt → graceful shutdown

## Особенности реализации

| Особенность | Описание |
|-------------|---------|
| Двойное хранение счёта | `claimed_*` (заявлено хозяином) + `*_goals` (финальное после подтверждения) |
| Статус лиги | `registration → active → finished/archived` — предотвращает удаление участников после жеребьёвки |
| ELO с team power | Бонус делает матчи асимметричными при разнице в мощности команды |
| Двухфазное подтверждение | Хозяин вводит → гость подтверждает/оспаривает → нет односторонних решений |
| Роли администраторов | `super_admin` управляет лигами и админами; `admin` только одобряет/разрешает |
| Групповой анонс | При установленном `GROUP_CHAT_ID` результаты публикуются в группе |
| ON CONFLICT DO UPDATE | Идемпотентная регистрация — повторный `/start` не создаёт дубликат |
| smartUpdate | Редактирует существующее сообщение или отправляет новое — меньше шума в чате |
