# ⚽ eFootball League Bot

Telegram-бот + веб-приложение для управления турнирами по eFootball.
Go (chi, pgx, Goose) + PostgreSQL + Next.js (статический экспорт, встроен в Go-бинарь).

---

## 🧩 Возможности

### Telegram-бот
- Регистрация (язык, имя, мощность команды, любимый клуб)
- Заявки в лиги, одобрение/отклонение администратором
- Заявка результата матча → подтверждение/спор соперником, эскалация админу при 3+ спорах
- Турнирная таблица, расписание, статистика, ELO-рейтинг и ранги
- Многоязычность: uz / ru / tg

### Веб-приложение
- Те же лиги/таблицы/расписание/статистика в браузере, вход через Google или Telegram
- **Турнирные форматы**: одиночный/двойной круг, группы + плей-офф, Swiss, Nations League, гибридный (группы → топ-N → кросс-посев плей-офф)
- **Сетка плей-офф** (bracket) с автогенерацией следующего раунда
- **Дедлайны раундов и напоминания** — автоматические уведомления в Telegram за 24ч/1ч до дедлайна
- **Достижения**: первая победа, хет-трик, серии побед (3/5/10), 10 голов, 5 «сухих» матчей, ветеран и др. — начисляются автоматически после подтверждения матча
- **Награды сезона / Зал Славы**: чемпион, лучший бомбардир, лучший рейтинг — выставляются автоматически при завершении лиги (финал плей-офф или ручная финализация админом)
- Карточки игроков, форма последних матчей
- Админ-панель: создание/архивация лиг, жеребьёвка, разрешение споров, управление дедлайнами, ручная финализация лиги

## 🗄️ База данных

Миграции Goose применяются автоматически при старте бота. Основные таблицы:

```
users            — игроки: telegram_id/email, рейтинг (ELO), ранг, team_power, любимый клуб, язык
seasons          — сезоны
leagues          — лиги: формат (rounds_type), группы, статус (registration/active/finished/archived)
league_members   — участники лиги + статистика (очки, W/D/L, голы, позиция)
matches          — матчи: claimed_* (заявлено) / *_goals (подтверждено), статус, стадия плей-офф
disputes         — архив споров с решением администратора
admins           — роли admin / super_admin
bracket_slots    — сетка плей-офф
round_deadlines  — дедлайны раундов + флаги отправленных напоминаний
achievements / user_achievements — справочник и начисленные достижения
season_awards    — награды Зала Славы (идемпотентны: ON CONFLICT по league_id+award_type)
```

## 🚀 Запуск

### 1. Переменные окружения

```bash
cp .env.example .env
# заполнить BOT_TOKEN, POSTGRES_DSN, JWT_SECRET, GOOGLE_CLIENT_ID, ADMIN_USERNAME/ADMIN_PASSWORD
```

### 2. Режим разработки (бот + API без встроенного UI)

```bash
go run -tags dev ./cmd/bot
```

Фронтенд запускается отдельно (Next.js dev-сервер):

```bash
cd web
cp .env.local.example .env.local   # NEXT_PUBLIC_API_URL=http://localhost:8080
npm install
npm run dev
```

### 3. Продакшн-сборка (один бинарь, фронтенд встроен)

```bash
cd web && npm install && npm run build   # генерирует cmd/bot/ui (не коммитится)
cd ..
go build -o bot ./cmd/bot
./bot
```

> `cmd/bot/ui` — артефакт сборки `next build`, в git не хранится (см. `.gitignore`).
> Для прод-сборки `NEXT_PUBLIC_API_URL` не задаётся — фронтенд ходит на тот же origin,
> где Go раздаёт и API, и статику.

### 4. Docker / Fly.io

```bash
docker-compose up -d
```

`Dockerfile` сам собирает фронтенд (`web-builder`), копирует результат в `cmd/bot/ui`
и собирает Go-бинарь — `cmd/bot/ui` из репозитория не требуется.
`fly.toml` использует тот же `Dockerfile` для деплоя на Fly.io.
